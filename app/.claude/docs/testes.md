# App tests

How to write and organize the app's tests (ADR 0015). Index in [app/CLAUDE.md](../../CLAUDE.md); invariants in the [root CLAUDE.md](../../../CLAUDE.md).

## Where each test lives

| Level | Folder | Run with |
| --- | --- | --- |
| Unit, widget and database | `test/` | `fvm flutter test` (host, no emulator) |
| Drift migration | `test/drift/` (generated by `make-migrations`) | `fvm flutter test` |
| E2E | `integration_test/` | `fvm flutter test integration_test` (emulator or device); written through the `create-e2e-test` skill |

`test/` mirrors the feature-first `lib/` (ADR 0018) file by file: `lib/x/y.dart` → `test/x/y_test.dart`. Helpers live in `test/helpers/` and are not `_test.dart` files, so they are exempt from the mirroring rule.

## Names

Description in English, with the requirement code first when there is one: `test('RF-02: reordering updates a single row', ...)`. An invariant test cites the RNF: `test('RNF-05: deleting a notebook only sets deleted_at', ...)`.

## Database (always, with real SQLite)

Every DAO, repository and query is tested against a fresh in-memory database per test. Do not mock the database or the DAOs. Use the `createTestDatabase()` helper from `test/helpers/test_database.dart`, which opens a new `AppDatabase` on `NativeDatabase.memory()` with `closeStreamsSynchronously: true` (avoids "A Timer is still pending" in widget tests):

```dart
late AppDatabase db;

setUp(() => db = createTestDatabase());
tearDown(() => db.close());
```

- That is why `AppDatabase` takes the `QueryExecutor` in its constructor; the production executor (`drift_flutter`) stays outside the class, in `databaseProvider`.
- Test what the UI consumes: the streams (`watch()`), not just one-off reads.

  ```dart
  expectLater(repo.watchPages(notebookId), emitsInOrder([isEmpty, hasLength(1)]));
  await repo.createPage(notebookId, title: 'A');
  ```

## Migrations

1. `build.yaml` registers the database under `drift_dev` → `databases` (`app_database: lib/core/database/app_database.dart`) and sets `store_date_time_values_as_text: true`; add any new database there.
2. On every table change: bump `schemaVersion` and run `fvm dart run drift_dev make-migrations`. The command exports the version's schema to `drift_schemas/`, generates the step-by-step migration helpers and the test in `test/drift/`.
3. Write the `vN → vN+1` migration with the generated helpers and complete the generated test (`SchemaVerifier`) with data: rows created in the old version must survive the new one.
4. Commit what the command generated in `drift_schemas/` and `test/drift/`. Exported schemas are never edited by hand. `test/drift/` is exempt from the `lib/` mirroring rule (STRUCT-03), since its tests have no source file of their own.

## Mocks with mocktail

Mock only interfaces above the database: sync (phase 2), clock, id generator, platform services.

```dart
class MockClock extends Mock implements Clock {}

final clock = MockClock();
when(() => clock.now()).thenReturn(DateTime.utc(2026, 10, 11));
```

- A custom type used with `any()` needs `registerFallbackValue(...)` in `setUpAll`.
- Prefer a simple fake (`class FakeX implements X`) when the test only needs data, not call verification.

## Riverpod

Inject the database, mocks and fakes through overrides, never through a global variable.

```dart
final container = ProviderContainer.test(overrides: [
  databaseProvider.overrideWithValue(db),
  clockProvider.overrideWithValue(clock),
]);
```

`ProviderContainer.test` disposes the container at the end of the test.

## Widget

Every screen and component with logic has a widget test, with the in-memory database and the same overrides:

```dart
await tester.pumpWidget(ProviderScope(
  overrides: [databaseProvider.overrideWithValue(db)],
  child: const MaterialApp(home: NotebooksScreen()),
));
```

- Drift streams use timers: close the database and `pump` before the test ends to avoid "A Timer is still pending".
- No golden tests for now.

## E2E (main flows)

Owned by the `create-e2e-test` skill (`app/.claude/skills/create-e2e-test/SKILL.md`): flow table, file skeleton, helpers, determinism, error paths and verification. Invoke it before writing or changing anything in `integration_test/`; this doc does not repeat its rules.

## Invariants with a fixed test

Each root invariant that applies to the app has at least one database or unit test:

- deleting only sets `deleted_at`, and queries ignore deleted records (RNF-05);
- IDs are UUID v7, generated without network (RNF-04);
- a notebook is born with the owner's row in `notebook_members` (ADR 0004);
- `created_by` and `updated_by` come from the anonymous local user before login (ADR 0011);
- archiving sets `notebook_members.archived_at` on the user's row, not `deleted_at` (ADR 0012);
- the app never increments `blocks.version` (ADR 0013);
- dates stored in UTC.

## Processes

- **A bug starts with a test:** write the test that reproduces the bug and watch it fail before fixing.
- **Determinism:** clock and UUID generator sit behind providers and are overridden in tests. No direct `DateTime.now()` or `Uuid()` in business rules. The e2e helper `pumpJotlineWithoutNetwork` also overrides both through `TestApp` (`FakeClock`, `SequentialIdGenerator`), so e2e flows are deterministic too.
- **Load (RNF-06):** the 10,000-page test gets `@Tags(['perf'])`. When creating the first one, declare the tag in `dart_test.yaml` with `skip`, so it stays out of the default `flutter test`, and run it with `fvm flutter test --tags perf --run-skipped` before a release.
- **Coverage:** `fvm flutter test --coverage` generates `coverage/lcov.info` (not committed). It is a signal for finding gaps; there is no minimum target.
